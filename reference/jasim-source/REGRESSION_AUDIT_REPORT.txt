5. CRITICAL MISSING PIECE: resolveStepInputs
════════════════════════════════════════════════════════════════════════════════

The user's Phase 2 instructions specifically ask to verify whether a function
like `resolveStepInputs` already exists.

FINDING: It does NOT exist anywhere in the codebase.

IMPACT: When Step A produces an output, Step B (which depends on A) does NOT
receive A's output in its inputs. The planner stores dependencies as step IDs,
but the runtime never merges dependency outputs into downstream step inputs.

REQUIRED FIX: Add resolveStepInputs() that:
  1. Reads the dependency step IDs from step.dependencies
  2. Fetches each dependency's outputs from the DB
  3. Merges them into the current step's inputs
  4. Handles template variables like "$step1.outputs"
