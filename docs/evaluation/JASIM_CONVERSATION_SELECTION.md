# JASIM — نفس الزرّ، في مكانٍ آخر، يبلغ نفس الحدّ

`VISIBLE_CONTROL != EXECUTION_PERMISSION`

---

## 1. العيب

حين يتولّى سطحُ المراجعة المُضيف، تعود شبكةُ الاكتشاف إلى رسالتها — وأزرارُها الستّة كانت
تذهب إلى `handleActionClick` التي **تشترط فقاعةً ذكيّةً مُسجَّلة**، وإلّا أجابت:

> «الإجراء … لا يملك سطحًا موثوقًا متاحًا الآن»

رفضٌ صادق، لكنّ ستّة أزرارٍ تبدو قابلةً للضغط تماماً كما كانت، وليست كذلك.

## 2. والفقاعة لم تكن فكرةَ الخادم قطّ

المُرسِل الموثوق يقرأ: **نوع الفعل، ونوع المرجع، والحمولة، ونسخة العرض، وهل يُحَلّ المرجع تحت
هذا المالك**. ولا يقرأ `source` ولا `presentationReference`، **ولا يعرف ما الفقاعة أصلاً**.

```
MESSAGE != SMART_BUBBLE
NEW_SMART_BUBBLE_FOR_EVERY_MESSAGE = 0
```

فالاشتراط كان **افتراضَ توجيهٍ في العميل**، والعلاج أن تبلغ الضغطةُ الحدَّ الموجود أصلاً: نفس
`dispatchWorkspaceAction`، نفس نوع الفعل، نفس الفحوص — وبمصدرٍ صادق `CONVERSATION` لا متنكّراً
في زيّ ورشة. والرسالةُ **لا تمنح شيئاً**، بل تُتيح بلوغ ما كان قائماً.

## 3. الآلية الحقيقية للزرّ الميّت — وكانت أعمق ممّا ظننت

`PresentationRenderer` كان يُمرّر المُعالِج هكذا:

```tsx
onAction={(actionId) => onAction?.(actionId)}
```

دالّةٌ **مُعرَّفةٌ دائماً** تلفّ مُعالِجاً اختيارياً. فشرطُ البطاقة نفسه `onAction &&` **لم يكن
ليتحقّق أبداً**، ورُسِم الزرّ سواءٌ وُجد من يستقبل الضغطة أم لا. وهذه آليةُ **كلّ** زرٍّ مُفعَّلٍ
عاجز، لا زرِّ المحادثة وحده.

والعلاج سطرٌ واحد: مرِّر المُعالِج كما هو، فيعني الشرطُ ما يقول — **لا مستقبِل، لا زرّ**.

## 4. سباقٌ حقيقيّ ظهر في الاختبار

ضغطتان متزامنتان أنتجتا **ربطَين فاعلَين** لـ`current:order`: كلٌّ قرأ «لا شيء حاليّ بعد» في
لقطته وأدرج. فصار لـ«الطلب الحالي» **جوابان**.

```
CURRENT_ORDER_HAS_TWO_ACTIVE_BINDINGS = 0
```

ولا مُزلاجَ في العميل: قفلٌ استشاريّ لكل `(محادثة، مفتاح)` داخل المعاملة نفسها — فلا تنتظر
الترتيبات والإشارات بعضها — **وفهرسٌ فريد جزئيّ** يجعل الثبات مِلكَ قاعدة البيانات لا مِلكَ
حُسن النيّة:

```sql
CREATE UNIQUE INDEX reference_bindings_one_active_idx
  ON reference_bindings ("conversationId", "referenceKey")
  WHERE "supersededAt" IS NULL;
```

## 5. الهدف هويّةٌ لا موضع

```
SELECT_BY_POSITION = 0 · SELECT_BY_CARD_INDEX = 0 · SELECT_BY_TITLE = 0
```

ومُثبَت: بطاقةٌ من مجموعة نتائج **سابقة**، بعد بحثٍ ثانٍ أعاد الترتيب، ما زالت تعمل على
مرجعها هي. و«الخامس» و«5» و«عنصر» لا تُحَلّ إلى شيء.

ومعرّفٌ اختلقه العميل **لا يشتري شيئاً**: الخادم يُعيد قراءة الشيء تحت هذا المالك ويقارن نسخته.

```
CLIENT_CAN_FORGE_CANDIDATE = 0
FORGED_MESSAGE_ACTION_CREATES_DRAFT = 0
```

## 6. ما قِيس في متصفّحٍ حقيقي — عالمٌ نظيف لكل مقاس

```
ENTITY_GRID (6 أزرار داخل المُضيف)
  → ضغط الثالثة  → DETAIL «كاشف تسرّب 4»  (الأزرار الستّة صارت في الفقاعة)
  → ضغط الخامسة من الفقاعة → DETAIL «كاشف تسرّب 2»
  → تحديث  → نفسه      → مغادرة وعودة → نفسه

toast في الضغطتين: «تم إرسال الإجراء إلى الحالة الموثوقة.»  ولا رفضَ واحد.
orders = 6 (ثلاثة مقاسات × ضغطتان)   active current:order = 1
agreements = 0  transactions = 0  payment_intents = 0  economic_proposals = 0
MOBILE_390X844 = PASS  MOBILE_430X932 = PASS  DESKTOP_1440X900 = PASS  hScroll = 0
```

## 7. ما لم يُبنَ

لا زرّ موافقة، ولا `CREATE_PROPOSAL`، ولا مُنفِّذ واجهةٍ عامّ، ولا فقاعةٌ لكل رسالة، ولا جدولٌ
جديد. المُضاف: مُعالِجٌ واحد يستدعي الإرسال الموجود بمصدرٍ صادق، وشرطٌ يقرّر الرسمَ من
القابلية، وقفلٌ وفهرسٌ يجعلان «الحاليّ» جواباً واحداً.
