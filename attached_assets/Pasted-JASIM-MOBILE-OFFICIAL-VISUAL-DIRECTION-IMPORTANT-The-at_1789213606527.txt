JASIM MOBILE — OFFICIAL VISUAL DIRECTION

IMPORTANT:
The attached reference image is now the OFFICIAL VISUAL NORTH STAR for JASIM Mobile.

Study the attached image carefully before modifying the UI.

This image defines HOW JASIM SHOULD FEEL AND LOOK FROM INSIDE THE MOBILE APP.

It does NOT define domain architecture.

Cars, laptops, jobs, health, travel, maintenance, shopping, etc. shown in the image are EXAMPLES ONLY.

DO NOT create:
CarApp
JobApp
ShoppingApp
TravelApp
MaintenanceApp
HealthApp
or domain-specific screens/components/routes.

JASIM remains:

ONE JASIM
ONE CONVERSATION
ONE GENERATIVE EXPERIENCE
ONE CANONICAL RUNTIME

1. THE MAIN PRODUCT IDEA
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The attached image represents the intended JASIM experience:

USER OPENS JASIM
↓
SEES ONE MAIN CONVERSATION
↓
TYPES NATURAL LANGUAGE
↓
JASIM UNDERSTANDS THE GOAL
↓
THE CONVERSATION GENERATES THE RIGHT UI
↓
THE GENERATED UI CAN CHANGE/MORPH AS THE TASK CHANGES
↓
ONGOING WORK CAN REMAIN AVAILABLE AS LIVING OBJECTS

The app must NOT feel like a normal app with dozens of fixed service pages.

The user should feel:

"I tell JASIM what I want, and the application forms itself around my request."

The main screen of JASIM is:

THE CONVERSATION.

Not:

dashboard
service directory
app launcher
category grid

The visual reference shows multiple capabilities, but inside the actual app they should emerge from the conversation.

The user may say:

"ابحث لي عن أفضل لابتوب تحت 300 دينار"

"قارن الأول والثالث"

"خذ الأول"

JASIM may generate an Approval surface.

Then:

"وافق"

The current experience may become Status / Timeline.

All of this happens while the user remains in ONE conversation.
