Implement the generic semantic projection for:

LIVING OBJECT

A Living Object represents:

SOMETHING DURABLE THAT CONTINUES AFTER THE CURRENT RESPONSE.

It is NOT new business truth.

It is a presentation projection over existing canonical durable objects.

Examples:

price monitor

active order

delivery

booking

negotiation

generated World

long-running Run

persistent project

ongoing selling process

subscription-related operation

Do NOT implement the visual Active Objects Rail yet.

2. PERMANENT RULE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

This rule is NON-NEGOTIABLE:

IF IT ENDS WITH THE RESPONSE
→ DO NOT CREATE A LIVING OBJECT

IF IT CONTINUES AFTER THE RESPONSE
→ A LIVING OBJECT MAY BE JUSTIFIED

Examples:

"كم سعر الذهب؟"
→ NO Living Object

"قارن هذه الثلاثة."
→ NO Living Object

"لخص هذا الملف."
→ NO Living Object by default

"راقب سعر الذهب."
→ Living Object justified

"تابع طلبي."
→ existing order may project as Living Object

"بع سيارتي وتابع المشترين."
→ Living Object justified

"ابن لي شركة نقل."
→ World may project as Living Object

The architecture must enforce this distinction generically.
