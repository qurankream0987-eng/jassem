# JASIM — TASK #14

## TRUSTED EXECUTION TRANCHE

### BUILD EXECUTION PROPOSALS + FINGERPRINTED APPROVALS BEFORE ANY PROVIDER EXECUTION

اعتمد أن المرحلة السابقة اكتملت وثبتت:

```text
General Reference Resolution = REAL
Reference Resolution Tests = PASS
Semantic Output Router = BASELINE
Durable Runs = BASELINE
Intent-only execution = BASELINE
No external side effects = VERIFIED
```

لا تعِد بناء هذه الطبقات.

الآن انتقل إلى Build داخل نفس المهمة #14.

---

# 1. الهدف من هذه tranche

نريد الفصل الصريح بين:

```text
USER INTENT
```

و:

```text
EXECUTION PROPOSAL
```

و:

```text
AUTHORIZED EXECUTION
```

هذه ليست نفس الأشياء.

المسار المطلوب:

```text
User Turn
↓
Semantic Intent
↓
Reference Resolution
↓
Execution Proposal
↓
Capability Validation
↓
Policy Evaluation
↓
Approval Requirement
↓
Fingerprint
↓
Authorized / Blocked / Awaiting Approval
```

وتتوقف هذه tranche هنا.

لا Provider execution بعد.

---

# 2. Execution Proposal يجب أن يصبح Aggregate/Contract واضحًا

أنشئ representation واضحة لاقتراح التنفيذ.

يجب أن يحتوي حسب تصميم المشروع على مفاهيم مثل:

```text
proposalId
ownerId
conversationId?
runId?
bubbleId?
worldId?
sourceMessageId?
intentType
targetReferences
capabilityId
capabilityVersion?
normalizedInputs
riskLevel
sideEffectType
policyContext
approvalRequirement
fingerprint
status
createdAt
updatedAt
```

استخدم أسماء المشروع الحالية إذا كانت أفضل.

لا تعتبر هذا Schema حرفيًا إلزاميًا.

---

# 3. Execution Proposal ليست Execution

إنشاء Proposal لا يعني:

```text
provider called
external side effect happened
action succeeded
```

يجب أن تسجل بوضوح:

```text
effects = none
```

حتى يتم الانتقال لاحقًا إلى Executor موثوق.

---

# 4. Proposal يجب أن تكون Immutable في جوهرها

بعد إنشاء Proposal وفingerprint:

لا تعدل المدخلات الحرجة في نفس Proposal بصمت.

إذا تغير:

```text
capability
target
critical inputs
policy-relevant values
amount
destination
scope
```

أنشئ Proposal/Revision جديدة أو أعد fingerprint حسب تصميم المشروع.

المهم:

> Approval القديمة لا تبقى صالحة لتكوين مختلف.

---

# 5. Capability ID يجب أن يكون Canonical

Proposal يجب أن تشير إلى Capability مسجلة في Registry.

مثال:

```text
publish.create
notification.send
schedule.create
entity.update
```

وليس:

```text
sell_car
hire_teacher
advertise_shop
```

---

# 6. Unknown Capability

إذا اقترح النموذج Capability غير مسجلة:

```text
proposal = BLOCKED
reason = UNKNOWN_CAPABILITY
```

ولا تحاول تنفيذها.

---

# 7. Capability Schema Validation

قبل إنشاء Proposal قابلة للموافقة:

تحقق من inputs عبر Schema الرسمية للCapability.

إذا المدخلات ناقصة:

```text
status = AWAITING_INPUT
```

إذا غير صالحة:

```text
status = INVALID
```

أو الحالة Canonical المناسبة.

---

# 8. Normalize inputs before fingerprinting

هذه نقطة مهمة جدًا.

لا تبنِ fingerprint على JSON خام غير canonical.

نفذ Canonical Normalization بحيث:

```text
{"price":200,"currency":"KWD"}
```

و:

```text
{"currency":"KWD","price":200}
```

ينتجان نفس fingerprint.

---

# 9. Fingerprint definition

الفingerprint يجب أن يربط على الأقل:

```text
capability identity
capability version if relevant
normalized critical inputs
resolved target references
owner/scope where relevant
policy-relevant execution context
```

---

# 10. لا تضع بيانات غير مستقرة في fingerprint بلا سبب

مثل:

```text
createdAt
UI label
display text
random ordering
```

إذا لم تكن تؤثر على معنى التنفيذ.

نريد fingerprint دلالية مستقرة.

---

# 11. Cryptographic fingerprint

استخدم Hash cryptographic مناسبًا للمشروع مثل SHA-256 أو ما يعادله.

مثال مفهومي:

```text
fingerprint =
HASH(
 capability
 + normalizedInputs
 + targetReferences
 + policyContext
)
```

لكن طبّق canonical serialization صحيحة.

---

# 12. Approval يجب أن ترتبط بالفingerprint

لا أريد:

```text
approved = true
```

على Run أو Task بشكل عام.

الصحيح:

```text
Approval
↓
proposalId
↓
executionFingerprint
```

---

# 13. Approval validity rule

الموافقة صالحة فقط إذا:

```text
currentExecutionFingerprint
==
approvedExecutionFingerprint
```

إذا اختلفا:

```text
approval = INVALIDATED
```

ويجب طلب Approval جديدة إذا كانت مطلوبة.
