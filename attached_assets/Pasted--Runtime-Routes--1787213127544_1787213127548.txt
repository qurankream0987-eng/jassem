ممتاز. تابع التنفيذ، لكن قبل إضافة المزيد من Runtime Routes ثبّت هذه القاعدة المعمارية حتى لا ننحرف أثناء البناء:

# 1. `bubbleId` يجب أن يكون علاقة اختيارية، لا شرطًا لكل Task

إضافة `bubbleId` إلى Task صحيحة إذا كانت العلاقة:

```text
Task
→ may reference Bubble
```

وليست:

```text
Every Task
→ must have Bubble
```

جاسم ليس Bubble-only Runtime.

---

# 2. الأشكال المختلفة للطلب يجب أن تبقى ممكنة

يجب أن يستطيع Runtime تمثيل جميع الحالات التالية:

## A. إجابة مباشرة

المستخدم:

> ما الأفضل بين هذه الخيارات؟

```text
Conversation
→ Message
→ Result
```

بدون World وبدون Persistent Bubble.

---

## B. Action مباشرة

المستخدم:

> أعلن عن هذا المنتج.

```text
Conversation
→ Task/Run
→ Capabilities
→ External Action
```

قد لا تحتاج Persistent Bubble.

---

## C. Workflow مستمرة

المستخدم:

> راقب سعر هذا المنتج وأخبرني عندما ينخفض.

```text
Conversation
→ Durable Run
→ Scheduler/Monitor
```

ولا يلزم إنشاء World كامل.

---

## D. إنشاء Bubble دائمة

المستخدم:

> أنشئ لي نظامًا أدير منه منتجاتي وطلباتي.

```text
Conversation
→ Task
→ Smart Bubble
→ Durable World Runtime
```

---

## E. تعديل Bubble موجودة

المستخدم:

> متجري الذي فيه الآيفون خفض سعره.

```text
Conversation
→ resolve existing Bubble
→ Task/Run referencing bubbleId
→ mutate existing World Runtime
```

---

# 3. العلاقة المقترحة

حافظ معماريًا على إمكانية:

```text
Task {
  conversationId
  bubbleId?: nullable
  ...
}
```

إذا كان هذا متوافقًا مع تصميم المشروع.

ولا تجعل `bubbleId NOT NULL` لمجرد أن Smart Bubbles أصبحت جزءًا أساسيًا من جاسم.

---

# 4. Bubble لا يجب أن تعتمد على Task واحدة

نفس Bubble يجب أن تستطيع امتلاك تاريخ من Tasks/Runs:

```text
Smart Bubble
├── Task A — create
├── Task B — add entity
├── Task C — change price
├── Task D — modify policy
├── Task E — advertise
└── Run F  — scheduled monitoring
```

Task تنتهي.

Bubble تستمر.

---

# 5. World الحالي لا تحذفه

قرار الحفاظ على World الحالي صحيح.

اجعل العلاقة:

```text
Smart Bubble
↓
optional durable World Runtime
```

بحيث World يبقى طبقة الحالة والتنفيذ الدائمة للBubble.

لا تعِد كتابة World إذا كان versioning/state/history الحالي يعمل.

---

# 6. لا تجعل Bubble مجرد alias للWorld

نحتاج فصل المسؤوليات:

```text
Smart Bubble
= user-facing identity + semantic surface + presentation/reference context

World Runtime
= durable entities + state + workflows + policies + permissions + versions
```

يمكن ربطهما بقوة، لكن لا تدمجهما في جدول واحد فقط لتسهيل التنفيذ إذا كان ذلك سيخلط مسؤولياتهما.

---

# 7. نفذ Schema validation الآن

شغّل:

```text
database/schema validation

generated-client typecheck
```

وأصلح أي failure قبل بناء Runtime routes فوق Schema غير مستقرة.

# 13. اختبار إلزامي قبل التوسع

# القاعدة التي لا يجوز كسرها

> A Bubble is available when the user's goal benefits from a persistent generative surface.

> A Bubble is not a prerequisite for Jasim to think, search, sell, buy, advertise, schedule, monitor, compare, or execute a workflow.

> `bubbleId` links work to a Bubble when one exists; it must not turn every Jasim operation into a platform.

تابع التنفيذ على هذا الأساس ولا تتوقف عند إنشاء الجداول.
