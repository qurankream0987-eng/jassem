5. PRODUCT PRIORITY IS NOT THE SAME AS TECHNICAL PRIORITY
=======================================================================

JASIM must be developed using TWO simultaneous priority axes.


AXIS A:
UNIVERSALITY / TECHNICAL LEVERAGE

Ask:

    Does this primitive unlock many unrelated use cases?


AXIS B:
ECONOMIC LEVERAGE

Ask:

    Does this primitive allow users to create or capture meaningful
    economic value?

    Can JASIM generate justified recurring or transaction revenue from
    this value?

    Does this increase retention, liquidity, frequency, GMV, or LTV?


A technically elegant capability with almost no user/economic leverage
must not outrank a general primitive that unlocks:

    commerce,
    hiring,
    services,
    recurring businesses,
    B2B,
    delivery,
    payments.
