3. WHAT IS BROKEN (Verified with Evidence)
════════════════════════════════════════════════════════════════════════════════

[CRITICAL] Bug #1: Step Inputs Are Never Passed
───────────────────────────────────────────────────────────────────────────────
File: api/core/task-runtime.ts
Lines: 274, 286, 336

  const capResult = await this.capabilityRegistry.execute(cap.id, {}, context);
                                                          ^^^^
  const result = await this.toolRuntime.invoke(tool.id, {}, context);
                                                     ^^^^
  const altResult = await this.capabilityRegistry.execute(alt.id, {}, context);
                                                           ^^^^

Impact: SEVERE. The planner generates step.inputs like:
  { "goal": "Book a flight to Paris", "intentType": "book", "entities": [...] }

The executor receives these inputs from the DB but passes {} to every
single capability and tool. This means:
- The LLM fallback in executeStepInternal receives no context
- Tools run with no parameters
- Capabilities execute with empty data

This is NOT a missing feature. This is a broken wire in the execution loop.

───────────────────────────────────────────────────────────────────────────────

executeStep queries:

───────────────────────────────────────────────────────────────────────────────
[CRITICAL] Bug #3: DAG Builder Uses Wrong Field for Dependencies
───────────────────────────────────────────────────────────────────────────────
File: api/core/task-runtime.ts Line 219

buildDAGLevels looks for:
  if (step.dependsOn) {
    const deps = typeof step.dependsOn === 'string' ? JSON.parse(step.dependsOn) : step.dependsOn;
    for (const depName of deps) {
      const depStep = steps.find((s) => s.name === depName);

But the planner stores:
  dependencies: node.dependencies   // Array of STEP IDs like "step_1_understand_goal"

And the fallback plan stores:
  dependsOn: JSON.stringify(['understand_goal'])  // Array of STEP NAMES

MISMATCH: The DAG builder looks for .dependsOn (step names) but the planner
stores .dependencies (step IDs). The DB schema has .dependencies (JSON array
of step IDs). No step will ever have .dependsOn set from the planner path.

Impact: ALL steps run in parallel in a single level. DAG ordering is ignored.
